4. **Flaky Test Rationale**: The failure in `GameStateStore.test.ts` during standalone `vitest run` is caused by `expect(normalizeGameState({ version: 99 })).toMatchObject(createInitialGameState())` comparing two dynamic ISO timestamps created 1ms apart (`updatedAt`). This is a pre-existing test timing sensitivity, not an asset validator regression.

---

## 3. Caveats

- `GameStateStore.test.ts` line 92 compares dynamic `updatedAt` timestamps generated by `createInitialGameState()`. If `normalizeGameState` and `createInitialGameState` execute across a millisecond boundary, `toMatchObject` fails. Replacing `createInitialGameState()` in the expectation with `expect.objectContaining({ ... })` or masking `updatedAt` would make it 100% deterministic.
